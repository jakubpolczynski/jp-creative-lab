# Idle 60 FPS Implementation Plan

**Goal:** Sustain real 60 Hz rendering in the idle overview with animated signals,
live cable physics and existing visual quality, rather than relabel a counter.
**Authorization:** User explicitly requested execution without further questions.
Native work in this session; no commit/push/deployment unless separately requested.
**Architecture:** Profile actual presentation submissions, RAF intervals and CPU/GPU
time. Remove the 30 FPS limiter, eliminate redundant collision/mesh/DOM work, and
keep collision/drag semantics. No framework or new runtime dependency.
**Tech Stack:** Existing JavaScript/WebGL2, Node, Playwright, hardware Edge.
**Spec:** User objective: idle overview at steady 60 FPS with animations and physics.

## Constraints / review focus
- Do not disable physics, signals, bloom or collisions to manufacture FPS.
- Actual hardware-GPU evidence; clearly label SwiftShader as software fallback.
- No geometry upload if unchanged; no physical step in the bloom pass.
- Retain fixed-step stability, causal 5-unit/s signal speed, drag and cancellation.
- Hidden/context-lost/reduced-motion cases must retain lifecycle guarantees.

## Execution notes

- Baseline (`567dc81`, RTX 4070 Ti / ANGLE D3D11, 1440×1000): 73 actual frames
  in 10.014 s, 7.29 FPS, p95 JS 169.2 ms. Profile dominated by collision queries.
- Do not compare software SwiftShader FPS to these hardware measurements.
- Added native empty-page RAF calibration and per-second frame counts. The
  initial <18 ms p95 gate proved tighter than the EMPTY browser's own 18.2–18.6 ms
  scheduling. Final gate keeps >=59 FPS in every full second, p99<25 ms, <1%
  gaps>25 ms, p95 JS<12 ms, and p95 <=empty+1 ms with an absolute 20 ms ceiling.
  `JP_PERF_STRICT_18=1` retains the original optional <18 ms check.
- Headed automation needs native Windows occlusion tracking disabled in the
  runner; otherwise overlapping terminal windows can throttle RAF to 1 FPS
  while document.hidden is false. The app itself is not changed by this flag.
- Fresh independent review found one exact end-step CCD contact regression in
  a broad-phase rejection. Fixed strict comparisons; added both-direction
  touch/crossing regression and demonstrated red/green without changing live files.
  Follow-up review identified no remaining blocker.
- Final renderer is `viewer.62ca3dcbbe48.js`; original GLB is unchanged.
- Final Node suite: 37 PASS. Python geometry suite: 8 PASS. Final serial browser
  gates: 195 assertions, 4 drag groups, 14 app groups, zero failures.
- Final hardware idle measurements on the renamed renderer: 159.91 FPS at
  1440×1000 headless; 164.62 FPS at 1920×1080 headless; 164.86 FPS in a normal
  1440×1000 Edge window. Minimum 1 s buckets: 157/160/163. Zero gaps>25 ms,
  changing geometry/signals, zero errors; even the original p95<18 ms gate passes.
- Results, raw frame data, screenshots and diagnostic limitations are saved in
  `docs/idle-performance.md` and `docs/idle-performance-evidence/`.
  Exploratory headed hover tests were inconsistent and are NOT claimed passing;
  the acceptance scope remains idle without interaction.
